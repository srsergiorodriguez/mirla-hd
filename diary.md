## 2026-10-26 — Audit, plan, and branch

**Branch:** `agent-dev` (created from `main`; not pushed)
**Scope:** Read-only audit of the plugin, theme, components, data editor, print layer, Publii internals, and release workflow; write the planning docs. No application code changed.

**What changed**
- Created `agent-dev`.
- Added `architecture.md`, `design-system.md`, `testing.md`, `plan.md`, `diary.md`.

**What I learned (current state)**
- The plugin source in the repo and the installed copy at `~/Documents/Publii/plugins/mirlaPlugin` are currently identical. Publii 0.47.5 resolves `appDir` to `~/Documents/Publii`, loads plugins with `fs.statSync` (follows symlinks) and `require()` (follows symlinks), so a directory symlink is viable.
- The theme lives at `input/themes/mirlaTheme` and is both the site theme and the release source. `assets/css/style.css` is generated by Publii; `assets/js/mirla-components.js` is generated by Vite. Both should be treated as build artifacts.
- The plugin is a 555-line CommonJS file that does parsing, validation, media resolution, HTML injection, item-page cloning, and report writing. It injects CSV values into HTML without escaping and throws on missing template pages, which is risky in single-page previews.
- The theme's context script (`window.MIRLA_CONTEXT`) is duplicated in `page.hbs`, `page-interactive.hbs`, and `post-interactive.hbs`.
- The root `input/themes/mirlaTheme/zine.js` is stale; the templates load `assets/js/zine.js`.
- `input/config/plugins/Mirla.json` is stale; the active config is `mirlaPlugin.json`. The docs mention a `galleryFilters` option that the plugin manifest does not expose.
- The 12 Svelte custom elements duplicate: data normalization (refs/scalars), search/filter/status controls, reset buttons, empty/error states, item cards, and the categorical palette. `MirlaProtocol` copies `MirlaTable`'s CSS verbatim (with a comment saying so).
- `--mirla-border` is defined locally in three components, not globally. The theme's `main.css` defines a global `--mirla-border` already.
- The data editor is a 1,313-line single HTML file with CDN dependencies (Pico, JSZip, PapaParse), inline styles, imperative DOM rendering, ES/EN i18n, and a complete CSV/ZIP/WebP/project-JSON workflow. Its state shape and export paths must be preserved.
- The crossmedia layer is a print template (`page-print.hbs`) + Paged.js + p5.js. There is no catalog. The print CSS is inline and hardcodes fonts/page size.
- `Source Code Pro` is referenced in `page-print.hbs` but not loaded.
- The release workflow zips the plugin, theme, and editor but does not build or test them.
- Runtime CDN dependencies: Pico, Shoelace, Google Fonts, OpenSeadragon, unpkg world atlas (map component). Offline workshops need a plan for this later.

**Decisions proposed (not yet approved)**
- ADR-003: symlink the repo plugin into `~/Documents/Publii/plugins`; CI zips the same source.
- ADR-004: generate the print catalog in the plugin through an `htmlOutput` modifier into a new theme print page, rather than a separate app.
- ADR-005: port the editor to Svelte only after a single-file/file:// spike passes.
- ADR-006: tokens live in the theme; components use `var(--mirla-*, fallback)`.
- ADR-007: keep public custom-element names/props unchanged during the refactor.

**Verified**
- Git worktree was clean before branching; `agent-dev` is the current branch.
- Publii 0.47.5 plugin loading code confirms symlink viability at the code level.
- Current repo plugin and installed plugin contents are identical (`diff -rq` empty).
- Current theme `input/themes/mirlaTheme` and installed theme copy are identical.

**Not done / next**
- Do not run the symlink yet: it modifies `~/Documents/Publii` outside the repo and needs explicit approval.
- Do not change any application code until the plan is approved.
- Next: approve Sprint 0, add the link/build/test scripts, verify the symlink with a real Publii preview, then start Sprint 1 (design tokens + data helpers + primitives).
- The component refactor should start with `MirlaIndex` and `MirlaTable`, because they share the most duplication.

**Open questions**
- Confirm catalog defaults (2 columns, 6 items/page, `label/autores/fecha/medio_impresion`, main images, grayscale).
- Confirm catalog scope (main table only for v1).
- Confirm font approach (Google presets + system + custom; self-hosted later).
- Confirm whether to push `agent-dev` to origin now or after Sprint 1.

## 2026-10-26 — Sprint 0: plugin dev loop, scripts, CI

**Branch:** `agent-dev`
**Scope:** Foundations only. No application code changed.

**What changed**
- Applied the plugin symlink:
  - `~/Documents/Publii/plugins/mirlaPlugin` → `~/Documents/Publii/sites/mirla-hd/mirlaPlugin`.
  - The previous installed copy was backed up to `~/Documents/Publii/plugin-backups/mirlaPlugin-20261026-101249/` (outside `plugins/`, so Publii does not list it as a second plugin).
- Added `scripts/link-plugin.sh` (dry-run default, `--apply`), `scripts/unlink-plugin.sh` (dry-run default, restore latest/specific backup), `scripts/link-plugin.ps1` (Windows junction).
- Added `scripts/check-plugin-loader.js`, which mirrors Publii's `readdir` → `stat` → `require` → `addEvents` path.
- Added `scripts/test-all.sh` and `scripts/build-all.sh`.
- Added `.github/workflows/ci.yml`: plugin syntax/manifest checks, component install/test/build, reproducible-bundle check, and conditional editor build once `data-editor/` exists.
- Updated `architecture.md`, `design-system.md`, and `plan.md` with the confirmed decisions (self-hosted fonts, catalog defaults, push policy, backup location).

**Why**
- Remove the duplicated plugin copy and make Publii load the same source that GitHub Actions packages.
- Make the dev loop explicit and reversible instead of relying on a manual copy.
- Establish reproducible builds before the component refactor begins.

**Verified**

- `node scripts/check-plugin-loader.js` reports:

  - `afterRender: priority 1`
- `scripts/link-plugin.sh` dry-run reports "Already linked".
- `scripts/unlink-plugin.sh` dry-run finds the correct backup.
- Link/unlink/rollback were exercised in an isolated temporary `PUBLII_HOME`; the backup was restored and the link recreated successfully.
- Full plugin `processDataset` was run against a temporary collection (real CSVs, symlinked images, temporary output):
  - 56 items (51 main + 5 secondary)
  - 24 protocol attributes
  - 56 item pages
  - `collection.json` + `collection-data.js` + report written
  - 1 pre-existing data warning: `WARNING parsing Protocol Protocol.csv: Some rows may be missing trailing commas.`
- `scripts/test-all.sh` passes all available checks.
- `scripts/build-all.sh` rebuilt `mirla-components.js` with no diff (249.16 kB, reproducible).
- CI YAML parses with Ruby YAML.
