## 2026-10-26 — Audit, plan, and branch

**Branch:** `agent-dev` (created from `main`; not pushed)
**Scope:** Read-only audit of the plugin, theme, components, data editor, print layer, Publii internals, and release workflow; write the planning docs. No application code changed.

**What changed**
- Created `agent-dev`.
- Added `architecture.md`, `design-system.md`, `testing.md`, `plan.md`, `diary.md`.

**What I learned (current state)**
- The plugin source in the repo and the installed copy at `~/Documents/Publii/plugins/mirlaPlugin` are currently identical. Publii 0.47.5 resolves `appDir` to `~/Documents/Publii`, loads plugins with `fs.statSync` (follows symlinks) and `require()` (follows symlinks), so a directory symlink is viable.
- The theme lives at `input/themes/mirlaTheme` and is both the site theme and the release source. `assets/css/style.css` is generated by Publii; `assets/js/mirla-components.js` is generated by Vite. Both should be treated as build artifacts.
- The plugin is a 555-line CommonJS file that does parsing, validation, media resolution, HTML injection, item-page cloning, and report writing. It injects CSV values into HTML without escaping and throws on missing template pages, which is risky in single-page previews.
- The theme's context script (`window.MIRLA_CONTEXT`) is duplicated in `page.hbs`, `page-interactive.hbs`, and `post-interactive.hbs`.
- The root `input/themes/mirlaTheme/zine.js` is stale; the templates load `assets/js/zine.js`.
- `input/config/plugins/Mirla.json` is stale; the active config is `mirlaPlugin.json`. The docs mention a `galleryFilters` option that the plugin manifest does not expose.
- The 12 Svelte custom elements duplicate: data normalization (refs/scalars), search/filter/status controls, reset buttons, empty/error states, item cards, and the categorical palette. `MirlaProtocol` copies `MirlaTable`'s CSS verbatim (with a comment saying so).
- `--mirla-border` is defined locally in three components, not globally. The theme's `main.css` defines a global `--mirla-border` already.
- The data editor is a 1,313-line single HTML file with CDN dependencies (Pico, JSZip, PapaParse), inline styles, imperative DOM rendering, ES/EN i18n, and a complete CSV/ZIP/WebP/project-JSON workflow. Its state shape and export paths must be preserved.
- The crossmedia layer is a print template (`page-print.hbs`) + Paged.js + p5.js. There is no catalog. The print CSS is inline and hardcodes fonts/page size.
- `Source Code Pro` is referenced in `page-print.hbs` but not loaded.
- The release workflow zips the plugin, theme, and editor but does not build or test them.
- Runtime CDN dependencies: Pico, Shoelace, Google Fonts, OpenSeadragon, unpkg world atlas (map component). Offline workshops need a plan for this later.

**Decisions proposed (not yet approved)**
- ADR-003: symlink the repo plugin into `~/Documents/Publii/plugins`; CI zips the same source.
- ADR-004: generate the print catalog in the plugin through an `htmlOutput` modifier into a new theme print page, rather than a separate app.
- ADR-005: port the editor to Svelte only after a single-file/file:// spike passes.
- ADR-006: tokens live in the theme; components use `var(--mirla-*, fallback)`.
- ADR-007: keep public custom-element names/props unchanged during the refactor.
